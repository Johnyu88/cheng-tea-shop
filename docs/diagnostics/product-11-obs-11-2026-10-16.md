## 範圍與正式只讀基準

本次只整理隔離診斷候選與操作文件，未修改正式 Caddy、正式應用容器、商品資料、照片、訂單、Tailscale、DNS 或 CLOUD 工作。

- 正式 image 與候選原始碼 provenance 未完全證實，本套件不改變此風險。

## 隔離候選

候選設定：[obs11-caddy-config.txt](./obs11-caddy-config.txt)

- 記錄時間、method、path、status、duration 與遮罩後關聯 ID。
- 移除 query string。
- 刪除 Cookie、Authorization、Proxy-Authorization、session token 標頭。
- 不記錄 request body、照片、商品內容或個資。
- rolling file：單檔 1 MiB、保留 2 檔、最長 24 小時。
- 正式啟用時必須使用獨立診斷目錄，不得寫入商品資料目錄。

## 隔離驗證

| 項目 | 結果 | 證據 |
|---|---|---|
| access log | PASS | 修正版合成 POST 產生時間、POST、無 query path、status 201、duration、關聯 ID |
| 敏感欄位遮罩 | PASS | 合成 Cookie／Authorization／session token 未出現在 log |
| 容量與保留設定 | PASS（設定驗證） | 1 MiB／2 檔／24 小時已載入候選設定 |
| 隔離 reload | PASS | `caddy validate` 與 admin reload 載入候選設定，合成 POST 回 HTTP 201 |
| reload 失敗回退 | PASS | 真正無效設定 validate/reload exit 1，原設定仍回 HTTP 201 |
| 正式應用診斷能力 | BLOCKED | 正式 image 沒有可用 write／sync 診斷證據 |

隔離修正紀錄：初版 URI filter 在測試中被 Caddy 解析成錯誤替換，造成 404；未進入正式環境。改用 `log_append` 記錄 path、並刪除完整 URI 後，重新 validate／reload 驗證。另確認「空 reverse_proxy 上游」會被 Caddy 接受但造成 503，因此不作為失敗回退測試；改用未識別 directive，驗證 reload 確實被拒絕且原設定持續服務。

代理 HTTP 200／201 只代表代理完成轉發，不能單獨證明 catalog 持久化。完整取證仍需要應用回應商品 ID，以及 request ID、write status、sync status 或等價伺服器證據。

## 正式啟用最小變更與風險

需另行核准：

1. 以正式 Caddyfile 為基礎加入短期、獨立目錄 access log。
2. `caddy validate` 通過後 reload；不停止或重建正式應用容器。
3. 設定固定診斷窗口、檔案上限與保留期限。
4. 若要確認持久化／同步，另需核准正式應用最小診斷欄位；Caddy log 本身不足。

停止條件：配置驗證或 reload 失敗、代理異常、log 出現 query／Cookie／Authorization／body／照片／個資，或任何需要修改正式資料與應用的要求。

## 正式單次測試清單

1. 核准設定、窗口、操作者與回退條件。
2. 保存原始 Caddyfile 雜湊與非敏感設定摘要。
3. 建立權限受限的獨立診斷 log 目錄，不放在 `/app/data` 或 `/app/catalog-sync`。
4. validate 後 reload，確認 `:10001` 與 `/healthz` 正常。
5. 請使用者只按一次「儲存商品」，不得重送。
6. 用關聯 ID 核對手機→Caddy 的 method、path、status、時間與 duration。
7. 用應用端證據核對商品 ID、write status、sync status；只有代理 status 時標記「尚未確認持久化」。
8. 只讀核對 catalog 數量與新 ID；已寫入時不得再次新增。
9. 驗收後 reload 還原原設定，停止 log 並依核准流程安全清除診斷檔。

## 回退清單

1. 停止新的診斷操作。
2. 還原原正式 Caddyfile。
3. validate 通過後 reload。
4. 確認 Caddy、`:10001`、`:8090` 與正式應用可連線。
5. 確認診斷 log 不再新增；不停止、不重建正式應用容器。
