## 診斷鏈設計

`Caddy access log → application response headers → application JSON log`

- Caddy access log 不記錄完整 request URI、request headers 或 request body；只保留 path、method、status、duration，以及應用 response headers 中的診斷欄位。
- 應用接受符合限制的 `x-demo-request-id`；沒有安全關聯 ID 時產生 UUID。
- 應用記錄 `received` 與 `completed` 事件，欄位只有 request ID、instance ID、method、HTTP status、duration、write status、sync status。
- 商品名稱、價格、照片、電話、姓名、Cookie、Token、密碼及 request body 不進診斷 log。
- 診斷輸出失敗會被隔離，不得使商品寫入失敗。

1. 取得總管與使用者對正式 Caddy 短期 log、應用診斷、操作窗口及回退條件的明確核准。
2. 保存原正式 Caddyfile 雜湊與非敏感設定摘要；不得建立正式商品測試資料。
3. 在獨立權限受限目錄啟用短期 access log；先 validate，再 reload，不停止應用容器。
4. 確認 `:10001`、Caddy health 與應用入口正常。

6. 以 Caddy path／status／duration 與 response request ID 關聯應用 `received`／`completed` log。
7. 只有在應用 write status 為 persisted 且同一 ID 的 GET／catalog 讀取確認後，才判定持久化；代理 200／201 不足以判定。
8. 核對 catalog 筆數、商品 ID、照片、draft／published 狀態；已寫入不得再次新增。
9. 測試完成後 reload 原設定，確認診斷 log 停止新增，再依核准流程清除診斷檔。

## 停止與回退條件

- validate／reload 失敗、Caddy 或應用健康異常：停止手機操作，reload 原設定。
- log 出現 query、request headers、body、照片或個資：立即停用診斷並保留事件摘要。
- 只有代理 status、沒有應用持久化證據：不得宣稱成功，不得要求重送。
- 任何資料備份、正式容器重啟、正式部署、候選切換或 provenance 不明的替換，均需另行核准。
