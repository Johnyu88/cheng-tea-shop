# 年長使用者參與走查：本機測試準備

這份文件供主持人預演與未來真人走查使用。Wave 7-A 只完成本機準備，現在不需要真人參與，也不啟動正式 preview、付費服務或外部部署。

## 一、主持人腳本

### 開始前說明

「今天不是考試，也不是測試您。是在看網站是否容易理解。如果任何地方不清楚，請直接說出您正在想什麼；我只會記錄，不會責怪您。您可以隨時休息或停止。」

請主持人準備：

- 一台桌機或筆電：瀏覽器視窗約 1280px 寬。
- 一支手機或窄視窗：寬度 360px、高度約 800px。
- 計時器與本文件的問題紀錄表。
- 只使用合成資料：姓名「陳小姐」、手機「0912000000」、地址「茶行路 1 號」。

### 進行規則

1. 一次只念一項任務，不先指出按鈕位置。
2. 先等待參與者自行嘗試；若停頓，問「您現在在找什麼？」而不是「請按這裡」。
3. 連續約 30 秒沒有進展時，記錄「需要提示」，再給中性提示：「請繼續找下一步，不用擔心按錯。」
4. 每項任務完成後詢問：「剛才哪裡最清楚？哪裡最不清楚？」
5. 不要求輸入真實姓名、電話、地址、付款資料或上傳真實照片。

## 二、購物任務清單

| 編號 | 給參與者的任務 | 完成條件 | 記錄重點 |
|---|---|---|---|
| T1 | 「請在首頁找一款您想了解的茶，說說您怎麼知道它是什麼茶。」 | 能指出茶名、口感或規格中的至少一項，並開啟商品詳情 | 是否理解商品卡、價格、商品照片準備中的意思 |
| T2 | 「請查看這款茶是否有貨，選擇 2 份加入購物車。」 | 商品詳情顯示有貨，數量為 2，購物車可見正確品項與小計 | 數量控制、供貨狀態、價格與小計理解 |
| T3 | 「請從購物車前往結帳，填入合成資料，走到確認訂單。」 | 依序完成聯絡資料與配送資料，看到確認訂單畫面 | 導覽、欄位標籤、下一步位置、資料是否保留 |
| T4 | 「請故意不填手機就按下一步，再修正。」 | 看見清楚錯誤提示，補上手機後能繼續，姓名仍保留 | 錯誤位置、文字理解、修正後資料保留 |
| T5 | 「請回到購物車，確認剛才的茶與數量還在。」 | 能返回並確認品項、數量、小計 | 返回方式、狀態保留、是否迷路 |
| T6 | 「請到商品上架原型，建立一個叫春茶的 150g 商品，價格 1200，選烏龍茶，標記有貨，先存成草稿。」 | 商品草稿頁完成最低欄位並看見草稿儲存成功 | 字體、欄位標籤、選單、儲存狀態、是否理解這是原型 |
| T7 | 「請產生介紹草稿，看看內容是否只使用您填的資料，再切換電腦版與手機版預覽。」 | 介紹可編輯、兩種預覽可切換，沒有自行捏造產地或功效 | 商品理解、文案可信度、預覽辨識 |
| T8 | 「如果內容確認無誤，請勾選確認並上架。」 | 先看到確認勾選，再看到合成商品上架成功 | 確認門檻、成功訊息、是否誤以為已正式上架 |

建議至少完成 T1–T5；T6–T8 是店家操作員情境，可在同一次走查或另一場進行。若時間不足，優先保留 T2、T3、T4、T6。

## 三、觀察項目

每項任務至少記錄一次以下觀察，不要只記「喜歡／不喜歡」。

| 類別 | 觀察問題 | 可記錄的證據 |
|---|---|---|
| 字體與閱讀 | 是否需要放大、靠近螢幕或重讀？標籤與錯誤文字是否看得懂？ | 連續閱讀時間、漏讀欄位、主動放大或改變姿勢 |
| 按鈕大小 | 是否能一次點到？是否誤觸相鄰控制？手機上是否需要精準瞄準？ | 點擊次數、誤觸、是否需要主持人指出位置 |
| 導覽 | 是否知道目前在哪裡、下一步去哪裡、如何返回？ | 迷路、使用瀏覽器返回、重複點擊、詢問「現在在哪裡」 |
| 商品理解 | 是否分辨茶名、口感、規格、價格、供貨狀態與 placeholder？ | 能否用自己的話重述；是否把 placeholder 當成真實照片 |
| 加入購物車 | 是否理解加入後的結果與數量控制？ | 是否尋找購物車、是否發現數量、小計是否合理 |
| Checkout | 是否理解聯絡、配送、確認三步？是否知道尚未使用真實付款？ | 步驟順序、欄位理解、返回後資料是否保留 |
| 錯誤提示 | 是否看到、讀懂並知道如何修正？ | 首次發現時間、修正動作、是否資料消失、是否重複提交 |

## 四、問題紀錄格式

每個問題單獨一筆，使用以下格式：

```markdown
### OBS-YYYYMMDD-01
- 任務：T4
- 頁面／viewport：`/checkout`／360×800
- 類型：blocker | friction | comprehension | accessibility | visual | content
- 嚴重度：P0 無法完成 | P1 需要主持人介入 | P2 可完成但明顯困惑 | P3 細節改善
- 觀察到的行為：參與者實際做了什麼、停頓多久、說了什麼（只記必要內容）
- 預期行為：依任務的完成條件
- 可能原因：字體 | 按鈕 | 導覽 | 商品資訊 | checkout | 錯誤提示 | 其他
- 是否重現：未重現 | 偶爾 | 每次
- 螢幕或錄影證據：僅填本機檔名；不得放入姓名、電話、地址或其他個資
- 建議下一步：最小可行修正或需要再次確認的問題
```

禁止在紀錄中保存真實姓名、電話、地址、付款資料、帳號、照片或錄音；若參與者不慎輸入，立即清除並只記錄發生類型。

## 五、成功／失敗判定

### 單一任務

- 成功：參與者不需指出控制位置即可完成任務，最多接受一次中性提示，且能說明自己完成了什麼。
- 部分成功：完成結果正確，但需要一次以上提示、反覆尋找，或無法說明結果；記為 P2 或可用性觀察。
- 失敗：主持人必須指出控制、代為操作，或參與者放棄／進入錯誤流程；若影響主要購物任務，記為 P1。

### Wave 7-B 本機準備通過線

- T1–T5 每項至少有一次完整成功紀錄；T6–T8 若執行，最低欄位流程不可出現 P0。
- 不得發現阻止主要購物路徑的 P0。
- 任何 P1 都要在下一次真人走查前修正或明確標記為待決策。
- 商品 placeholder、合成 checkout、Mock 上架成功不得被參與者誤解為真實照片、真實付款或正式上架；若發生，記為 comprehension P1/P2。
- 走查資料只保存在本機專案外的受控筆記位置，清除任何測試輸入後才可分享摘要。

## 六、本機測試環境

在目前隔離工作樹執行：

```powershell
node node_modules/next/dist/bin/next dev
```

瀏覽器開啟 `http://localhost:3000/`。若要測窄版，使用 DevTools responsive viewport `360 × 800`；桌機可使用約 `1280 × 800`。本機測試只使用 Mock service，不需要 GitHub、Docker、雲端、付款服務、登入或網路帳戶。

首頁第一次載入可能短暫顯示「正在整理茶品」；主持人應等「查看茶品」等主要入口出現後才開始 T1。若隔離工作樹的 dev server 因 `node_modules` junction 無法穩定載入，可使用已驗證的本機 standalone server 於另一個未占用 port，仍不得視為正式部署：`$env:PORT='3001'; node .next/standalone/server.js`，再開啟 `http://localhost:3001/`。

自動回歸可在另一個終端執行：

```powershell
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc --noEmit --incremental false
node node_modules/eslint/bin/eslint.js .
```

前台瀏覽器關卡（需要已安裝 Playwright Chromium／WebKit）：

```powershell
$env:CI='1'; node node_modules/@playwright/test/cli.js test e2e/baseline.spec.ts e2e/product-cart.spec.ts e2e/checkout-product-draft.spec.ts --project=chromium --workers=1 --reporter=line
$env:CI='1'; node node_modules/@playwright/test/cli.js test e2e/baseline.spec.ts e2e/product-cart.spec.ts e2e/checkout-product-draft.spec.ts --project=webkit --workers=1 --reporter=line
```

若只做人工走查，無需先執行 production build，也不要為此啟動 preview 或安裝付費服務。結束時以 `Ctrl+C` 停止本機 server，並清除瀏覽器中的測試頁面內容。

主持人 dry run 的自動化輔助指令與最新紀錄：

```powershell
$env:BASE_URL='http://localhost:3001'; node docs/testing/older-user-walkthrough-dry-run.mjs
```

這個指令只驗證路徑與控制存在，不模擬真人理解，也不能取代真人走查。
