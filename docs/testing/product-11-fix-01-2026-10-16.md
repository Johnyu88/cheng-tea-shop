## Root-cause boundary

The candidate confirms a real code-level risk: the original catalog store serialized writes only within one process, so independent store instances could race. The candidate adds a file lock and atomic durable write sequence. This is evidence for the fix design, not proof that the 2026-10-16 live incident was caused by different instances or by a front-end false-success path. Formal incident causality remains unconfirmed because the formal service was intentionally not touched.
