# 陳老師茶行目前最終規格清單 v1

## 1. 品牌
- 對外主品牌：陳老師茶行。
- 專案儲存庫名稱維持 `cheng-tea-shop`。
- 品牌風格維持「山霧自然」：霧綠、米白、茶褐，溫暖、平實、不誇張。
- 網站文字像陳老師親自介紹，不使用療效、誇大或無證據宣稱。

## 2. 茶葉商城正式分類
商城固定使用以下十種正式茶類，順序固定：

1. 台灣野生山茶
2. 綠茶
3. 白茶
4. 黃茶
5. 青茶（烏龍茶）
6. 紅茶
7. 黑茶（普洱茶）
8. 花茶（窨花茶）
9. 特殊茶
10. 老茶

規則：
- 「老茶」是第十種正式茶類，與其他九類同級。
- 「禮盒」與「茶具」不屬於第一版茶葉商城分類，從商城分類與選單中移除。
- 商品上架時茶類使用固定選項，不由操作人員自由新增第十一類。

## 3. 口感標籤
以下只作第二層風味／導購標籤，不取代正式茶類：
- 清香
- 甘甜
- 濃郁
- 焙火

單一商品：
- 必須有一個主要茶類。
- 可有多個口感標籤。

## 4. 首頁
首頁維持既有規格：
1. 茶山雲霧主視覺、品牌短句與「開始選茶」。
2. 茶類導覽與口感導購。
3. 三款人工指定精選茶品。
4. 陳老師／茶行故事。
5. 「來店喝茶」次要入口。
6. 付款、配送與安心購買說明。
7. 地址、營業資訊、地圖與聯絡方式。

禁止：
- 自動播放影音。
- 倒數計時。
- 壓迫式促銷彈窗。
- 假稀缺。
- 誤導產地或商品照片。

## 5. 商品目錄
- 實際營運目標至少 40 種茶品，但系統不得設定 40 筆硬上限。
- 每筆商品可為草稿或公開。
- 完成一筆即可個別公開。
- 售完商品仍可展示，但不可加入購物車。
- 缺少商品照時使用統一品牌預設圖並標示「商品照片準備中」。
- 不得拿其他茶品照片代替。

## 6. 商品卡與詳情
商品卡只顯示：
- 照片
- 茶名
- 價格
- 一句口感
- 售完狀態

商品詳情頁優先顯示：
- 商品照片
- 茶名
- 口感
- 價格
- 有貨／售完
- 加入購物車

故事、產地、製程與沖泡說明放在購買資訊之後。

## 7. 長輩友善商品上架
第一版每次只建立一項單一規格商品。

最低必要欄位：
1. 茶名
2. 單一規格
3. 價格
4. 茶類
5. 供貨狀態：有貨／售完

規則：
- 手機與電腦都可操作。
- 大字、大按鈕、白話用語。
- 自動儲存草稿。
- 照片或輸入失敗不得清除已填資料。
- 發布前提供預覽。
- AI 只產生草稿，不得自行發布。
- AI 不得編造產地、年份、療效或其他未提供資訊。
- 第一版不做多規格、精確庫存、批次匯入。

## 8. 購物與結帳
- 顧客不必註冊即可購買。
- 手機結帳維持三步驟：
  1. 聯絡資料
  2. 配送
  3. 付款
- 手機號碼必填。
- Email 選填。
- 錯誤或網路中斷時保留已填有效資料。
- 付款處理中禁止重複送出。

## 9. 配送與付款
第一版：
- 宅配
- 到店取貨

付款：
- 信用卡
- LINE Pay
- 到店取貨可保留到店付款

其他：
- 固定運費可設定。
- 滿額免運門檻可設定。
- 不把金額寫死在前台。
- 第一版不做超商物流與貨到付款。

## 10. 缺貨處理
若下單後發現實際庫存不足：
1. 標記人工處理。
2. 24 小時內電話聯絡顧客。
3. 提供換貨或退款。
4. 記錄處理結果。
5. 已付款訂單依付款服務的正式退款流程處理。

## 11. 聯絡與來店喝茶
- 一鍵打電話為主要協助方式。
- LINE 為次要方式。
- 第一版不做自動訂位與茶席排程系統。

## 12. 技術與工程邊界
維持：
**Website First → Mock API → ERP Reuse → API Integration**

目前已完成 Wave 1 基線。

前端：
- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- pnpm

原則：
- 前台元件只依賴專案自有 Service/API Interface。
- 前期接 Mock Adapter。
- 後期才接 ERP Adapter。
- ERP、支付、物流皆需經 Adapter 隔離。
- 不從零打造完整 ERP，先評估成熟開源方案。

## 13. 目前明確不做
- 禮盒商城分類
- 茶具商城分類
- 多規格商品
- 精確庫存
- 批次匯入
- 強制會員
- 超商物流
- 貨到付款
- 自動茶席訂位
- 完整 ERP 自建
- 壓迫式促銷

- 商城分類只有十種正式茶類。
- 禮盒、茶具不存在於第一版商城分類與導覽。
- 口感只作第二層標籤。
- 其他已核准規格維持不變。
- 不因模板或既有程式重新引入已刪除分類。
