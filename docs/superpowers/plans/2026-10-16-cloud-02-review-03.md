# CLOUD-02-REVIEW-03 GCP Deployment Preparation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or the project QA/Security review process. This plan is documentation and contract-test preparation only; it does not authorize cloud operations.

**Goal:** Prepare a reviewable, cost-protected GCP staging path and expose the PostgreSQL and lifecycle gaps without touching cloud or production resources.

**Architecture:** Reuse the existing standalone Next.js Docker artifact on Cloud Run, with separate GCP projects, Cloud SQL PostgreSQL, private Cloud Storage, Secret Manager, IAM and Logging. Render remains a production candidate; Demo SQLite/JSON remains synthetic and isolated.

**Tech Stack:** Next.js standalone Docker, PostgreSQL, Cloud Run, Cloud SQL, Cloud Storage, Secret Manager, IAM, Cloud Logging, PowerShell read-only inventory, static contract checks.

**Spec:** `docs/superpowers/specs/2026-10-16-cloud-02-formal-cloud-architecture-design.md`

## Global constraints

- No GCP/Render resource creation, API enablement, billing upgrade, deployment, DNS change or data migration.
- No Acer, 4090, formal site, real customer data, real orders or real photos changed.
- Hermes checks are read-only; without GCP access they remain BLOCKED.
- The reference PostgreSQL DDL is never executed against a live database.
- Unexecuted iPhone, GCP, backup and restore checks must remain PREPARED/NOT RUN or BLOCKED.

## Review focus

- Cloud SQL stopped state still billing storage/IP — verify against provider inventory, not VM status alone.
- Cloud Storage versions/soft-deleted objects — verify lifecycle and retained bytes before cleanup.
- PostgreSQL status/amount/inventory races — verify contract matrix before implementation.
- Trial expiry data loss — verify export/checksum evidence before 2026-11-13.
- Public HTTPS versus Cloud Run IAM — verify storefront public reachability and merchant app auth separately.
