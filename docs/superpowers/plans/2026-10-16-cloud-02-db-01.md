# CLOUD-02-DB-01 PostgreSQL Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four PostgreSQL contract gaps found in CLOUD-02-REVIEW-03 and prove them against a disposable local PostgreSQL database without touching production data.

**Architecture:** Add an additive, repeatable reference migration containing deferred amount checks, a locked inventory reservation function, an explicit order transition function, and request-hash-bound idempotency claims. Exercise the migration and contracts through Vitest using the `pg` client and a test-only PostgreSQL connection; do not wire the Demo SQLite/JSON runtime to this migration.

**Tech Stack:** PostgreSQL 14+, SQL functions/triggers, Node.js 24, TypeScript, Vitest, `pg`, Docker for the disposable local database.

**Spec:** `docs/architecture/cloud-02-postgresql-validation.md` and `docs/architecture/cloud-02-postgresql-schema.sql`

## Global Constraints

- Do not execute the reference schema or migration against Render, GCP, Acer, 4090, the formal site, or real data.
- Use only synthetic fixtures in a disposable local PostgreSQL database.
- Preserve existing Demo SQLite/JSON behavior and existing tests.
- Do not merge `main` or enter CLOUD-03.
- Migration must be additive, repeatable, and reject incompatible schema markers before changing data.
- Money is integer TWD; browser-supplied totals are never trusted.

## Review Focus

- A replay with the same idempotency key and same request hash returns the original resource; a different hash is rejected.
- A concurrent final-unit reservation has exactly one success and never produces negative inventory.
- A transaction that inserts an order with mismatched line, subtotal, shipping, total, or confirmed payment amount is rejected at commit.
- A shipment transition is rejected when payment is unconfirmed or packing has no confirmed photo, and accepted only after both gates pass.
- Re-running the migration leaves schema version and contract objects unchanged and refuses an incompatible marker.
