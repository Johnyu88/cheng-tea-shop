# Phase 1 品牌與漸進式商品目錄規格

- 日期：2026-09-14
- 狀態：已確認
- 階段定位：Phase 1 第四個部分里程碑
- 實作狀態：網站程式尚未開始

## 1. Objective

確認網站公開品牌、至少 40 種茶品的可擴充目錄、陳老師逐筆慢慢輸入的長輩友善流程，以及缺少商品照片時不誤導顧客的替代規則。

## 2. Brand identity

- 網站主名稱：龍映茗茶。
- 「陳老師茶行」是熟客稱呼，保留於品牌故事、搜尋說明與必要輔助文字。
- 專案儲存庫名稱可維持 `cheng-tea-shop`，不代表網站公開名稱。
- 公司法定資訊於實作前再依店家提供的正式資料核對，不從照片自行推定。

## 3. Catalog scale and visibility

- 系統必須穩定支援至少 40 種茶品。
- 40 是營運目標，不是資料筆數上限；不得寫死最大 40 筆。
- 不先建立 40 筆空白商品，也不捏造商品名稱、價格或說明。
- 每筆商品有草稿與公開狀態。
- 完成一筆即可獨立公開，其他未完成商品維持私人草稿。
- 公開商品售完時仍可展示，但不得加入購物車。

## 4. Elder-friendly one-page entry

第一版採單頁簡表，每次建立一項單一規格商品。

最低必要欄位：

1. 茶名。
2. 單一規格。
3. 價格。
4. 茶類。
5. 供貨狀態：有貨或售完。

可稍後補充：

- 一至三張實拍照片。
- 口感標籤。
- 香氣、產地、發酵、烘焙、沖泡方式及商品故事。
- 經人工確認的 AI 介紹草稿。

介面要求：

- 大字、大按鈕、可見標籤與白話用語。
- 自動儲存草稿，輸入或照片失敗不清除已填資料。
- 發布前顯示手機與桌機預覽。
- 必須由陳老師明確按下發布；AI 不得自行公開。
- 不在第一版加入批次匯入、精確庫存或多規格編輯。

## 5. Customer catalog discovery

- 首頁先用口感入口幫助不懂茶名的新客。
- 完整目錄同時提供口感與茶類篩選。
- 單一商品具有一個主要茶類，可具有多個口感標籤。
- 口感初始方向沿用：清香、甘甜、濃郁、焙火；口感是風味標籤，不取代正式茶類。
- 正式茶類固定為十類：
  1. 台灣野生山茶
  2. 綠茶
  3. 白茶
  4. 黃茶
  5. 青茶（烏龍茶）
  6. 紅茶
  7. 黑茶（普洱茶）
  8. 花茶（窨花茶）
  9. 特殊茶
  10. 老茶
- 「老茶」是第十個正式茶類，與前九類同級，不作跨茶類專區或額外標籤層。
- 首頁只顯示三款人工指定精選商品；40 種以上商品由完整目錄承載。
- 沒有符合條件時顯示清楚空狀態並提供「查看全部茶品」。

## 6. Photo fallback

- 沒有實拍照片的商品可使用統一龍映茗茶品牌預設圖。
- 預設圖必須清楚標示「商品照片準備中」。
- 不得使用另一款茶的照片作替代。
- 補上正式照片時只更新媒體資料，保留商品識別碼、網址與既有訂單關聯。
- 店家目前提供的照片已由游老師確認為店家拍攝／上傳，且同意網站公開使用；實作時優先取得原始檔。
- 第三方素材仍須保留授權與署名證據。

## 7. Claims and data safety

- 「無毒」、產地、年份、製茶者、療效或其他可驗證資訊，沒有證據時不得公開。
- AI 只能依陳老師已提供的資料生成草稿，不得補猜。
- 草稿商品不得出現在公開搜尋、網站地圖、商品 API 的公開結果或推薦區。
- 價格與規格改動必須由店家明確儲存；既有訂單保留成交時的商品快照。

## 8. Mock API boundary

前端實作階段以 Mock API 驗證下列穩定介面概念：

- `Product`：識別碼、名稱、單一規格、價格、茶類、口感標籤、供貨與發布狀態、圖片狀態。
- `CatalogQuery`：依茶類、口感與公開狀態篩選。
- `FeaturedProduct`：三款人工指定首頁精選。
- `ProductDraft`：自動儲存與明確發布。

前端元件不得直接綁定未來 ERP 的資料表或專有欄位。

## 9. Acceptance criteria

- 文件一致顯示公開主品牌為龍映茗茶。
- 系統目標為至少 40 種且沒有 40 筆硬上限。
- 可逐筆建立、儲存草稿與獨立公開。
- 最低五個欄位足以建立第一版商品草稿。
- 顧客可依口感與十個正式茶類尋找商品。
- 首頁維持三款人工精選。
- 缺圖商品使用有文字標示的統一品牌預設圖。
- 不捏造 40 種商品、照片、產地或宣稱。
- Phase 1 維持進行中，網站程式尚未開始。

## 10. Out of scope

- 一次建立 40 筆空白或虛構商品。
- 批次匯入與試算表編輯。
- 多規格商品。
- 精確庫存數量。
- ERP 選型與串接。
- 正式付款、物流與生產部署。
