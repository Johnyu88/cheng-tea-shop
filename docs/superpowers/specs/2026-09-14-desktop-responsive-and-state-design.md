# Phase 1 桌機、響應式與必要狀態設計規格

- 日期：2026-09-14
- 狀態：已確認並可寫入正式文件
- 階段定位：Phase 1 第二個部分里程碑
- 實作狀態：尚未開始網站程式開發

## 1. 目標

把已確認的手機優先 Wireframe 延伸到桌機和平板，並補齊購物流程的必要狀態與年長使用者操作保護，使後續實作不必猜測版面重排、錯誤恢復或多商品呈現方式。

## 2. 適用範圍

本規格涵蓋：

- 桌機首頁。
- 桌機商品詳情。
- 桌機與平板結帳。
- 多商品訂單摘要。
- 載入、空內容、錯誤、售完、付款與成功狀態。
- 年長使用者結帳求助與暫存規則。

不涵蓋：

- 正式前端框架選擇。
- 網站程式實作。
- Mock API 或 ERP 實作。
- 真實付款串接。
- 最終品牌攝影與完整正式文案。

## 3. 桌機首頁

採用「平衡清楚型」：

- 首屏左側放品牌文字與「開始選茶」，右側放真實茶山主視覺。
- 桌機導覽清楚顯示選茶、品牌資訊與購物車。
- 首頁資訊順序沿用手機版，不因畫面變寬而改變顧客理解順序。
- 四張口感選茶卡保持同等重要，不增加複雜篩選。
- 精選茶品在寬螢幕以三欄呈現。
- 茶行故事、來店喝茶、安心購買與聯絡資訊依序向下排列。

## 4. 桌機商品詳情

採用標準雙欄型：

- 左側約 56%：主照片與最多三張縮圖。
- 右側約 44%：口感、茶名、價格、有貨／售完、加入購物車、配送與庫存不足說明。
- 首屏必須同時看見主要照片及核心購買資訊。
- 故事、產地、製程與沖泡方式放在首屏後方。
- 售完商品保留內容，但購買按鈕停用，並提供「看看其他相近口感」入口。

## 5. 桌機三步驟結帳

桌機採雙欄：

- 左欄依序完成聯絡資料、配送、付款與確認。
- 右欄顯示訂單摘要。
- 每一步顯示目前位置，並可返回修改。
- 手機號碼必填，Email 選填。
- 不要求註冊會員。
- 表單錯誤、頁面重新整理或短暫網路中斷時，不清除已輸入內容。

## 6. 多商品訂單摘要

右側摘要分成三個區塊：

1. 商品。
2. 配送方式與運費。
3. 商品小計與目前合計。

商品顯示規則：

- 1～3 項商品全部顯示。
- 4 項以上預設顯示前三項。
- 顯示「查看另外 N 件商品」按鈕，展開後可逐項核對並再次收合。
- 每項顯示照片、茶名、規格、數量及金額。
- 摘要頂端保留「修改購物車」。
- 合計不可因商品展開／收合而離開摘要區。
- 不使用摘要區內的固定高度捲動框，以免長輩漏看商品。

## 7. 響應式規則

代表性驗證寬度：360px、768px、1024px、1440px。

- 1024px 以上：首頁、商品詳情及結帳可使用已確認的桌機雙欄。
- 低於 1024px：切換單欄，避免壓縮表單、文字或觸控目標。
- 平板結帳採單欄，訂單摘要放在表單上方並可展開。
- 單欄順序固定為主要任務在前、輔助資訊在後；結帳例外為先顯示可展開的訂單摘要，再顯示當前表單步驟。
- 表單欄位不可因畫面變窄而小於已確認的高度和字級。
- 觸控目標維持至少 48 × 48px。
- 不依賴滑鼠 hover 才能取得重要資訊或操作。

## 8. 表單錯誤

- 頁面上方先以白話顯示錯誤數量與原因。
- 問題欄位同時顯示清楚的行內訊息。
- 焦點移至第一個需要修正的欄位。
- 已正確填寫的資料完整保留。
- 不只使用顏色表示錯誤。
- 修正後使用「修改後繼續」返回原流程。

## 9. 付款狀態

### 9.1 處理中

- 清楚顯示正在確認付款。
- 暫停重複送出。
- 顯示付款方式與訂單金額。
- 等待過久時，先查詢付款結果，禁止直接建立第二筆付款。

### 9.2 付款失敗

- 明確說明付款沒有完成。
- 保留商品、聯絡資料、配送資料與訂單內容。
- 提供「再試一次」及「改用其他付款方式」。
- 說明目前沒有成立重複訂單。
- 提供一鍵打電話的主要求助入口，LINE 為次要入口。

### 9.3 訂購成功

- 顯示訂單編號、配送方式、付款狀態及總金額。
- 提供查看訂單內容與回到首頁。
- 說明後續通知方式。
- 若實際庫存不足，茶行會在 24 小時內電話聯絡並提供換貨或退款。

## 10. 其他必要狀態

### 10.1 載入中

- 使用與最終商品卡相同尺寸的骨架版面。
- 載入完成不得造成明顯版面跳動。
- 載入效果不得持續閃爍或造成干擾。

### 10.2 空購物車

- 清楚說明購物車尚無商品。
- 提供「開始選茶」主要動作與回首頁次要動作。
- 不要求先登入或註冊。

### 10.3 網路錯誤

- 清楚說明目前無法更新資料。
- 保留購物車和本次瀏覽已輸入的結帳資料。
- 提供重新載入。
- 提供電話主要求助入口與 LINE 次要入口。

### 10.4 商品售完

- 商品照片、故事及沖泡方式繼續顯示。
- 顯示「目前售完」文字。
- 停用加入購物車。
- 提供相近口感商品入口。
- 不使用倒數、催促或假稀缺文案。

## 11. 年長使用者操作保護

本次以代表性年長使用者情境進行設計走查，確認以下規則：

- 結帳求助以一鍵打電話為主要入口，LINE 為次要入口。
- 每個畫面只突出一個主要動作。
- 錯誤發生時以白話說明，不要求使用者理解技術術語。
- 購物車可跨瀏覽階段保留。
- 姓名、電話、Email、地址等個人資料只在本次瀏覽期間暫存。
- 個人資料在完成訂單、主動取消或瀏覽階段失效後清除。
- 不把付款卡號或第三方付款憑證存入前端暫存。
- 返回上一個步驟時保留本次瀏覽已填內容。

這是設計走查，不等同於真實使用者測試。可操作原型完成後，仍須邀請實際年長使用者進行操作驗證。

## 12. 驗收條件

- 桌機首頁符合平衡清楚型版面。
- 桌機商品詳情符合左圖右購買資訊。
- 桌機結帳符合左側三步驟、右側訂單摘要。
- 平板結帳切換單欄。
- 多商品摘要依 1～3 項全顯示、4 項以上先顯示前三項的規則運作。
- 所有錯誤和付款狀態保留適用資料並提供可復原動作。
- 求助入口以電話優先。
- 四個代表性寬度皆無內容重疊、水平溢出或不可操作的控制元件。
- 鍵盤、觸控與輔助科技不依賴 hover。
- 未導入前端框架或正式網站程式。
