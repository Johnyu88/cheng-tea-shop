## 1. 共同規則

- 不修改 Caddy、Tailscale Funnel/Serve、DNS、埠號對應。
- 不在終端機、log、聊天或 repo 印出任何環境變數的**值**、密碼、cookie、token。需要時只列環境變數**名稱**。
- 舊容器與舊 image **一律保留**（只停止、不刪除），作為回退目標。
- 每次切換都記錄：Git SHA、image 名稱與 digest、容器名稱與 ID、時間、測試結果、回退指令，事後寫進 `HANDOFF.md`。
- 任何一步結果和預期不同：**停下來回報，不要臨場改做法**。

## 4. 後台部署（`:10001`，會寫正式資料）

以 `docs/testing/product-11-gate-08-2026-10-16.md` 與 `docs/testing/product-11-release-07-2026-10-16.md` 的檢查清單為準，以下是摘要與這次的差異。

### 4.1 不要直接執行舊的 production-switch

`tools/prod-admin-23` 的 `production-switch` 寫死了 PROD-ADMIN-24 的來源與候選 ID（來源 `tea-private-v5-prod-admin-03-live`、候選 image `prod-admin-14-2be6be0`）。這些已經是過去式，**照原樣執行會因身分不符而拒絕**（這是正確行為）。要用這個工具，需另開一張工單（PROD-ADMIN-25）把預期值更新為：

- 來源：`tea-private-v5-prod-admin-24-live` / `tea-nextjs:prod-admin-14-2be6be0`（ID 與 digest 以唯讀查詢為準）
- 候選：`tea-nextjs:prod-admin-605e806`（ID 以建置結果為準）
- 備份路徑：本次 4.3 產生的備份

更新後跑 `tools/prod-admin-23/tests`，經使用者審核再使用。不用工具也可以，但必須達到同樣的保護：先停寫、保留舊容器、健康檢查失敗自動恢復。

### 4.2 掛載相容性測試（候選，獨立資料）

PRODUCT-11 的 lock / fsync / atomic rename 尚未在 Acer 的 Windows bind mount 上驗證（SECURITY-04 文件標為 UNKNOWN）。正式切換前：

1. 把正式資料**複製**到獨立目錄（例如 `C:\data\tea-staging\prod-admin-605e806-staging`），不要掛正式目錄。
2. 用新 image 在獨立埠起候選容器，掛這個複本。
3. 用合成商品驗證：新增後拿到商品編號、同一登入讀回存在、重啟容器後仍存在、草稿不出現在公開目錄、公開同步失敗時顯示「勿重複新增」且不會產生第二筆。
4. 驗證完停止並移除候選與複本。

### 4.3 正式切換（需使用者當下授權）

1. 公告維護窗口，從入口停止後台寫入（不能只靠「大家先別按」）；確認沒有進行中的新增或修改。
2. 備份：`catalog.json`、`publication.json`、`catalog-media`、公開 `media`、`packing-photos`，以及資料所有者要求的訂單／登入相關 SQLite。記錄 UTC 時間、大小、SHA-256，並做一次還原讀取測試。備份不得放進 repo 或聊天。
3. 切換前清點（只記數量與 ID，不記內容）：商品總數、每個 ID、草稿／上架狀態、照片引用。
4. 以相同掛載、埠（`127.0.0.1:8130`）、網路、指令、環境變數建立新容器並啟動；舊容器 `tea-private-v5-prod-admin-24-live` 停止但保留。
5. 驗證：健康、登入、同一登入讀取後台商品列表；數量與所有 ID、草稿／上架狀態、照片都和切換前一致；公開目錄只有上架商品。
6. 新增一筆合成測試商品**需另外取得同意**；若做，必須驗證拿到編號、讀回存在、重啟後存在、公開同步狀態，事後依使用者指示處理該筆。
7. 全部通過、記錄完成，經使用者同意後才解除停寫。

**回退條件**：容器起不來、掛載路徑不同、任何既有 ID 不見、照片打不開、草稿被公開、同步不一致、或出現無法確認的寫入。

**回退**：停止新容器，啟動 `tea-private-v5-prod-admin-24-live`（以 digest `sha256:e4be4719…` 確認是原 image），再做健康與商品列表唯讀核對。資料要不要還原，需先獨立確認備份 checksum 與目標路徑，不可自動覆蓋。
